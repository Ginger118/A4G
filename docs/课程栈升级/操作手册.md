# 序流 v0.5 操作手册：课程存储与语义检索

核对日期：2026-11-15。工作目录：`/Users/zz/Desktop/A4G`。保留三栏流式聊天和正式名称。本轮已实测 MinIO、Milvus、Ollama EmbeddingGemma 与 DeepSeek，测试资料为自造教学制度，不是真实企业制度。

## 一、组件与课程对应

| 课程能力 | 当前实现 | 学习入口 |
|---|---|---|
| DAY6 原件存储 | 私有 MinIO，PDF/TXT/MD 原件读回 | documents.py / OriginalStore |
| DAY6 向量入库 | Milvus 2.6.15，固定片段主键，按用户与模型版本分集合 | repositories/milvus.py |
| DAY7 文档提取 | PyMuPDF 逐页解析，保留页码/偏移/哈希 | documents.py / ingest_pdf |
| 文本切分 | LangChain RecursiveCharacterTextSplitter，420 字符、重叠60 | rag.py / splitter |
| 语义嵌入 | Ollama 内本地运行 EmbeddingGemma Q8_0，768维 | embeddings.py |
| DAY7/9 流程图 | 意图、澄清、检索、回答/草案、校验 | upstream/graph.py |
| 模型与输出 | ChatDeepSeek、SSE 真实增量、三栏 React UI | llm.py、streaming.py、ChatWorkspace.tsx |
| 应用记录 | SQLite，用户、会话、来源、任务和图检查点 | storage.py、upstream/service.py |

这些是课程核心链路的对应，不表示把全部 DAY6-DAY11 功能都搬入项目。没有新增混合检索、重排、OCR、生产集群和研究显式规划执行。

## 二、启动

在 VS Code 打开工作目录，在终端执行：

```bash
cd /Users/zz/Desktop/A4G
uv sync --locked --extra enterprise
python3 scripts/course_stack.py init
python3 scripts/course_stack.py up
uv run --locked --extra enterprise python run.py --course --use-authorized-deepseek-env
```

前提：Docker Desktop 和 Ollama 已运行；本机已安装课程镜像 `day6-minio:source-20250422`、`day6-milvus:2.6.15`、`quay.io/coreos/etcd:v3.5.25`。这些镜像沿用桌面 LangChain DAY6 的构建成果，本轮没有重建镜像。新机器需先复现 DAY6：目录 `/Users/zz/Desktop/langchain/企业级RAG全栈实战（DAY6-DAY11）/day6/enterprise`，按其操作手册及 `docker/build_minio.py` 准备相同镜像，再启动本项目；不要把仅复制仓库误认为镜像也复制完毕。A4G 使用独立容器、独立数据卷和独立端口，不修改课程容器。

嵌入模型已在本机就绪；新机器可使用项目固定来源安装脚本：

```bash
uv run --locked --extra enterprise python scripts/install_course_embedding.py
```

脚本从公开 ggml-org 仓库下载固定版本的 GGUF，校验 SHA256 后导入 Ollama 本机别名 `embeddinggemma:300m`。本轮官方 Ollama 拉取因分发地址校验失败，改用该公开仓库文件下载、续传、哈希校验及本地导入，最终成功。约334MB文件，网络中断时保留缓存并报告失败。来源见同目录 `模型来源.json`。模型供应商通用 `ollama pull embeddinggemma:300m` 可能得到不同量化/修订，不能混用旧索引；模型变更后重启应用并迁移。

`init` 只在 `.course.env` 不存在时生成本机随机存储凭据，权限0600，已被Git忽略；不覆盖 `.env`。`--course` 载入 `.course.env`，覆盖同名配置。模型密钥仍取原 `.env` 或已授权环境，仅向已授权 DeepSeek 地址调用。新机器没有旧授权环境时，自行在本机 `.env` 填写 `AGENT_API_KEY`，启动时省略 `--use-authorized-deepseek-env`。

前端修改后：

```bash
cd /Users/zz/Desktop/A4G/src/frontend
npm ci --ignore-scripts
npm run build
```

## 四、旧资料迁移与重启

```bash
cd /Users/zz/Desktop/A4G
uv run --locked --extra enterprise python scripts/migrate_course_knowledge.py
```

保留资产ID、页码、偏移、原本本地原件；为每份资料先写MinIO及向量，成功才更新该资料元数据。失败时当前资料不发布迁移成功，已完成资料仍有效，修复服务后可重跑。迁移不是跨存储事务，失败可能留下不可检索的孤立对象/向量，本版不自动清理；SQL授权与资料过滤不允许它们出现在答案中。迁移不修改用户原件，不迁移CSV/报告的应用存储位置。切换模型或维度会使用另一集合，旧索引保留；不自动删除。

本轮第一次迁移旧知识4份；加入本轮2份合成资料后，重跑迁移6份，固定主键不新增重复片段。仅存储容器的持久化验收：

```bash
docker compose --env-file .course.env -f docker/course-compose.yaml restart minio milvus
# 等Milvus健康端口19191返回200后再运行：
uv run --locked --extra enterprise python scripts/verify_course_persistence.py
```

预期原件读回与检索通过；新进程将 `embed_documents` 替换成抛错函数，证明检索没有临时重嵌文档。本脚本要求先执行完整验收，且操作者确实按上一步重启了存储。`course_stack.py stop`停止服务但保留数据卷；不要使用 `down -v`。
