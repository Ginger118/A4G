# A4G 启动、配置与重启速查

核对2026-11-17。工作目录 `/Users/zz/Desktop/A4G`。本次核对启动源码与官方命令语义，未执行重启或配置变更。

## 服务组成

- React是前端框架，Vite是开发服务器，npm是命令/依赖管理入口。
- FastAPI是后端框架，Uvicorn是服务器；本项目run.py负责先加载课程配置再启动Uvicorn。
- Docker Compose三个容器：Milvus向量库、MinIO原件存储、etcd元数据依赖。Docker Desktop先处于运行状态。
- Ollama是额外本机服务，提供EmbeddingGemma向量，监听11434。
- SQLite是应用嵌入式数据库文件，不是另一个服务器；DeepSeek是云API，无本地服务可重启。当前无Redis/MySQL服务依赖。

## A. 日常使用：只开8018即可

配置文件：`.env`保存模型API配置（AGENT_API_BASE、AGENT_API_KEY、AGENT_MODEL等），`.course.env`保存课程存储/嵌入配置。不要修改config/.env.example来填真实密钥。配置读取顺序：--course先读取.course.env并覆盖同名进程变量；随后.env仅填补尚未设置的项。模型凭据不放进命令行/报告。

```sh
cd /Users/zz/Desktop/A4G
open -a Docker
open -a Ollama
```

等待Docker Desktop/Ollama就绪后执行：

```sh
cd /Users/zz/Desktop/A4G
python3 scripts/course_stack.py up
uv sync --locked --extra enterprise
npm ci --prefix src/frontend
npm run build --prefix src/frontend
uv run --locked --extra enterprise python run.py --course
```

uv sync/npm ci主要用于首次或依赖锁变更；前端未改且dist存在时无需每次构建。打开 http://127.0.0.1:8018/ 。构建版前端没有单独npm常驻进程，FastAPI同时提供静态页面与API。

最后一行默认从本机私密.env配置模型。若明确选择复用已授权环境中的ANTHROPIC_API_KEY，才改用：

```sh
uv run --locked --extra enterprise python run.py --course --use-authorized-deepseek-env
```

该选项固定目标api.deepseek.com，需启动终端实际具备已授权环境。它会优先从现有进程环境设置AGENT_API_KEY；如果打算改为.env中的新密钥，请省略该选项，并检查终端是否已导出同名AGENT_API_KEY。不要输出变量实际值。启动配置不是全局热更新。

## C. 停止与重启应用

先等运行任务完成。在启动该程序的终端按Ctrl+C，再运行原启动命令。若该进程由其他工具启动、没有终端可按Ctrl+C，先定位：

```sh
lsof -nP -iTCP:8018 -sTCP:LISTEN
```

检查对应PID的命令（把12345换成上一步的实际数字）：

```sh
ps -p 12345 -o command=
```

仅确认属于A4G后执行：

```sh
kill -TERM 12345
```

确认端口释放后再启动run.py。不要用pkill python等广泛停止命令。开发前端同理检查5178端口，优先在其终端Ctrl+C。

构建版前端改代码后：

```sh
cd /Users/zz/Desktop/A4G
npm run build --prefix src/frontend
```

通常浏览器刷新即可，Python未改则无需重启；首次创建dist或新增静态路由挂载需重启后端。遇到旧页面可用浏览器强制刷新。开发模式前端代码通常热更新，无需build。

## D. Docker容器启停

```sh
cd /Users/zz/Desktop/A4G
python3 scripts/course_stack.py status
python3 scripts/course_stack.py stop
python3 scripts/course_stack.py up
```

未改配置，只重启现有三件套：

```sh
cd /Users/zz/Desktop/A4G
docker compose --env-file .course.env -f docker/course-compose.yaml restart
```

只重启Milvus：

```sh
docker compose --env-file .course.env -f docker/course-compose.yaml restart milvus
```

查看近期日志（避免在聊天/公共报告粘贴完整配置或日志）：

```sh
docker compose --env-file .course.env -f docker/course-compose.yaml logs --tail=50 milvus minio etcd
```

修改compose文件或容器环境变量后：

```sh
cd /Users/zz/Desktop/A4G
docker compose --env-file .course.env -f docker/course-compose.yaml up -d --force-recreate
```

restart不重新读取容器环境；up可按新定义重建，force-recreate明确强制重建并保留已挂载卷。若改MinIO访问凭据，需让Milvus与应用配置同步；修改这些配置后同时重启后端。不要使用down -v，它会删除知识库数据卷。

## E. Ollama

本机装有Ollama.app。未运行时：

```sh
open -a Ollama
ollama list
curl --max-time 5 http://127.0.0.1:11434/api/tags
```

若使用macOS应用管理Ollama，需要重启时先在菜单栏选择Quit Ollama，待其退出后运行open -a Ollama。命令行方式可请求退出已安装的应用：

```sh
osascript -e 'tell application "Ollama" to quit'
```

待退出后：

```sh
open -a Ollama
```

如果采用前台服务方式，则在其终端Ctrl+C后运行：

```sh
ollama serve
```

两种管理方式选一种，不要在11434已有服务时再开第二份。ollama stop 模型名只是卸载/停止该模型运行，不等于重启Ollama服务。macOS应用环境变量设置和服务重启的官方方式见下方来源。普通修改React/后端业务代码不需重启Ollama。

## F. 哪些修改需要什么动作

| 修改项 | 操作 |
|---|---|
| 前端代码/CSS，Vite开发模式 | 通常热更新 |
| 前端代码/CSS，8018构建模式 | npm run build后刷新 |
| vite.config.ts或前端环境变量 | 重启npm run dev；构建模式需重新build |
| Python业务代码、.env中的模型/密钥 | 停止并重启run.py，注意已导出的环境变量优先级 |
| .course.env的应用检索阈值、模型名/连接地址 | 重启后端；仅修改应用读取的值不一定需要重建Docker |
| Docker端口、映射、容器环境变量 | up -d --force-recreate；同步重启依赖此配置的应用 |
| Ollama进程配置/升级或服务异常 | 重启Ollama；应用连接配置改变时也重启后端 |
| 更换嵌入权重、模型、维度 | 迁移原知识向量后重启后端，旧向量不能直接混用 |
| 更改切分规则 | 后端重启影响新文档；旧文档需单独设计重切迁移，现有向量迁移脚本不重切 |
| 上传新资料 | 自动入库，不需要重启 |
| 修改召回Demo题集JSON | 下次读取/运行加载；刷新页面并重新评估，无需重启 |

更换嵌入模型时，先停止应用，保持Docker与Ollama运行；调整.course.env并确认新模型存在后：

```sh
cd /Users/zz/Desktop/A4G
uv run --locked --extra enterprise python scripts/migrate_course_knowledge.py
uv run --locked --extra enterprise python run.py --course
```

迁移脚本会重嵌全部现有知识并保留文档ID与原片段，不是日常重启的必要步骤。之后重新跑召回演示，不引用旧模型成绩。
