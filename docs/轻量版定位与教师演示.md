# 当前定位与教师演示

日期：2026-11-02。当前项目名为“基于 LangChain 的电力知识问答与辅助分析系统的设计与实现”。

## 当前主线

这是可以独立演示的 LLM 应用：对话、文件、切分、检索、引用、工具调用和报告组成闭环。电力只提供材料与轻量任务背景，无需深入专业电网建模。

约五分钟的演示：一分钟多轮对话；一分钟导入知识与展开切分片段；一分钟查询新文档独有信息并查看引用；一分半执行线路表分析并下载报告；半分钟打开模型与工具，展示 LangChain 组件及 Planner 接口。图片理解可作补充。

## 能够定位的实现

- ChatDeepSeek：llm.py 中 langchain_completion，包含异步调用、工具绑定和用量记录。
- RecursiveCharacterTextSplitter：rag.py 中 splitter，带中文分隔符、片段位置与配置。
- InMemoryVectorStore：rag.py 中用户隔离的向量索引；原文和片段保存于 SQLite。
- 多轮上下文：chat.py 与 messages 表，不同用户的同名会话不会相互读取。
- 四工具任务：tools/power.py；计算由代码执行，文字说明调用真实模型。
- 后续规划接口：agent/contracts.py 的 Planner，执行由 executor.py 独立负责。

LangChain 是应用框架，不是底层大模型。当前嵌入是本地字符哈希基线，不能介绍为预训练语义 Embedding。当前图片理解沿用独立模型调用。研究层的显式规划器尚未接入，不能把现有 Tool Calling 说成新的数学规划算法。

## 电力背景保留到什么程度

样例知识解释 MW、有功功率方向、给定限值、越限和人工复核。样例数据是三列线路表。系统做绝对值、除法、计数、检索和报告；不做潮流求解、N−1 仿真、故障诊断或真实调度。

## 未来如何发挥作用

已保留任务状态、工具参数、输出、执行记录和 Planner/Executor 分离。未来给工具补充前提、效果和版本条件，再接显式规划器。届时先用相同任务、工具、执行器和验收口径比较，不需要先重建界面、登录、文件、模型和报告。

当前不实施高维搜索、不确定性学习、复杂电网仿真、研究 Benchmark 或毕业论文。早先的《电力业务定位与研究对接方案》为历史候选；本文件为当前范围。
